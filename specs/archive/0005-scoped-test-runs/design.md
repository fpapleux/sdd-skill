## Approach
- **Two halves.** The script half (REQ-EVD-004, REQ-EVD-005, REQ-DEF-001 to REQ-DEF-004, REQ-DEF-006) lives in `skill/sdd/scripts/sdd.py`. The method half (ranges, the three test levels, the stop conditions, checkpoints, the triage report, what a capability is) is design work under project rule 1, listed under "Method changes" for the Planner.
- **One reader for the defect log.** `read_defect_log(project)` parses `specs/defects.md` once, keeps every line as written with its line number, and returns the rows or the first problem. The three defect commands, `check`, `analyze` and `status` all use it, so they agree on what is valid (REQ-DEF-006).
- **Writes never re-render.** `defect add` appends bytes to the end of the file; `decide` and `close` replace only the raw cell segments whose value changes, so every other byte stays as written (REQ-DEF-001 to REQ-DEF-003). Rejected: parsing the table into rows and writing it back, which would reformat padded headers and hand-edited rows.
- **The defect findings sit outside `analyze()`.** `cmd_check` and `cmd_analyze` add them to the report after it is built; `analyze()` itself, which the gates (`approve results`, `advance verified`, `archive`) call, never reads the log. Rejected: reading the log inside `analyze()`, which would let an invalid log refuse the verify gates, and the spec moved all blocking to a follow-up change.
- **The component command is a design rule inside `analyze()`,** next to the warning about a missing test command line, at the plan stage and later (REQ-EVD-004). It belongs to the change, like the other plan-stage checks.
- **`sort-failures` reuses check's scenario matching** (`scenario_pattern`, the verify-stage rule) and the task parser, and writes nothing (REQ-EVD-005).

## Components and interfaces
- **`design_text(path) -> str`** (REQ-EVD-004): the design the rule reads. Standard: `strip_comments` of design.md (empty when missing). Mini: the `## Design notes` section of the comment-stripped spec.md.
- **`check_component_command(design, err, warn)`** (REQ-EVD-004), called in `analyze()` when the stage is plan or later, after `check_plan`:
  - lines matching `^\s*[-*]\s*Test component\s*:[ \t]*(.*)$` (multiline, as `test_one`); an unbulleted line doesn't count (B5);
  - more than one line → error `the design has more than one "Test component:" line: keep one` (N3), and no further check;
  - none, or a text empty after `.strip().strip("`").strip()` → warning `the design has no "Test component:" line (or it is empty): the component checkpoints will be skipped` (B1, B2);
  - otherwise, each independently: no `{prefix}` → error `the "Test component:" command has no {prefix}: write where the capability's requirement prefix goes, e.g. "- Test component: \`python3 -m unittest -k REQ_{prefix}_\`"` (N1); `shlex.split` raising `ValueError` → error `the "Test component:" command has a quote that is not closed: <command>` (N2). Neither changes a file.
- **`test_component(design) -> str`**: the template text (`""` when absent), for the method and later tools; nothing in this change runs it.
- **Defect log format** (REQ-DEF-001, REQ-DEF-006): `specs/defects.md`, project-level, owned by the script.
  - `DEFECT_COLUMNS = ["ID", "Status", "Severity", "Decision", "Capability", "Change", "Test", "Evidence", "Close evidence"]`; header `| ID | Status | … | Close evidence |`; separator `| --- ` × 9 + `|`.
  - New log: `# Defects\n\n<header>\n<separator>\n<row>\n`.
  - Row text: `"| " + " | ".join(cells) + " |"`; a cell value has `|` written `\|`; empty cells give `|  |`.
  - Values: Status `open|closed`; Severity `critical|major|minor`; Decision `undecided|fix-now|later|wont-fix`; ID `D<n>`.
- **`read_defect_log(project) -> DefectLog`** (REQ-DEF-006): `exists`, `text`, `lines` (as written), `rows` (each: `line` number, `cells` unescaped by `table_cells`, `id`, `status`, `severity`, `decision`, `test`), `problem` (None or the first problem as `specs/defects.md line <k>: <what>`).
  - Comments are blanked to the same number of newlines first, so line numbers stay true; a table line is a line of that view starting with `|`.
  - Checks, in file order, stopping at the first problem: the first table line's trimmed cells equal `DEFECT_COLUMNS` (`the header must be the cells ID, Status, …, Close evidence`, N7); the second has every cell matching `:?-+:?` (`the second table line must be a separator row`); each later one has 9 cells (`a row needs 9 cells, found <k>`, N6), an ID matching `^D\d+$`, and allowed status, severity and decision (`severity "blocker" is not critical, major or minor`, N1), and an ID not seen before (`D1 is repeated (first on line <m>)`, N5).
  - A missing file is `exists=False`, no rows, no problem; a blank one has no rows and no problem.
- **`sdd.py defect add --test <name> --severity <critical|major|minor> [--capability <PREFIX>] [--change <id>]`** (REQ-DEF-001):
  - Order: `require_init`; the change (`project.current(args.change)`: "no active change" N6, `no change '<id>' in specs/changes/` N8, any status B6); the test name empty or only spaces → `the test name is empty` (N4); the capability; the log (`problem` → error, N1 and N7 of DEF-006); an open row with the same test → `<name> already has an open defect: D<k>` (N5); write.
  - Capability: `--capability` as written, else the first match of `REQ[-_]([A-Z][A-Z0-9]{1,5})[-_]\d+` (re.I) in the name, upper-cased (B3); none → `the test name carries no requirement ID: name the capability with --capability <PREFIX>` (N2). It must be a key of `project.registry()` or of the change's `parse_capabilities(fm["capabilities"])`, else `capability "<value>" is not a prefix of the living spec or of <change>` (N7).
  - n = 1 + the highest `D<n>` in the rows (closed ones count, S2), 1 with none.
  - Write: missing or blank file → the new-log text (S1); text with no table line → text (a `\n` added when it lacks one) + `\n<header>\n<separator>\n<row>\n` (B5); otherwise text (+ `\n` when needed) + `<row>\n` (S2, B1).
  - Prints `D<n> added (<severity>, <PREFIX>)`. `--severity` and `--test` are argparse `required`, severity with `choices` (exit 2, N1).
- **`sdd.py defect decide <id> <fix-now|later|wont-fix> [--evidence <text>]`** (REQ-DEF-002): `decision` is a positional with `choices` (exit 2, N1); `--evidence` is optional in argparse so its absence exits 1.
  - Order: evidence missing or blank → `a decision needs the operator's words: add --evidence "<what they said>"` (N6); id not `^D\d+$` → `"d1" is not a defect ID: write D<n>` (N3); no file → `no defect is logged (specs/defects.md does not exist)` (N5); `problem` → error; id not in rows → `no defect D9 in specs/defects.md` (N2); closed → `D1 is closed: its decision can't change` (N4).
  - Evidence: `\r\n`, `\r`, `\n` → space, stripped, `|` → `\|` (B3, B4).
  - Prints `D<n>: <decision>`.
- **`sdd.py defect close <id> [--evidence <text>]`** (REQ-DEF-003): the same lookup as decide (the same messages for the id form, missing log, invalid log and unknown id), then closed → `D1 is already closed` (N2); undecided → `D1 has no decision: the operator decides first (sdd.py defect decide)` (N1); evidence missing or blank → `closing needs --evidence: what fixed the defect, or why it is closed` (N6). Writes Status `closed` and Close evidence (same normalization); prints `D<n> closed`.
- **`set_cells(line, {index: value}) -> str`** (REQ-DEF-002, REQ-DEF-003): splits the raw line on `(?<!\\)\|`, replaces segment `1 + index` with `f" {value} "` only when its unescaped trimmed value differs, and joins with `|`. When no segment changes, the file is not written (DEF-002.B2).
- **`defect_counts(log) -> dict | None`** (REQ-DEF-004): None when `log.problem`, else `{"open", "critical", "undecided"}` over the open rows.
- **`defect_findings(project, report)`** (REQ-DEF-004, REQ-DEF-006), called by `cmd_check` after `analyze()` and by `cmd_analyze` after `full_analysis()`: sets `report.defects = defect_counts(log)`; adds `log.problem` as an error when `report.stage == "verify"` (DEF-006.N2), else as a warning (N3). `Report.defects` defaults to `{"open": 0, "critical": 0, "undecided": 0}`; `report_json` gains `"defects"`, so analyze keeps check's keys (REQ-ANL-001.S2); `Report.render` prints `open defects: <n> (<c> critical, <u> undecided)` just before `result:` when `defects` is set and `open > 0`.
- **`cmd_status`** (REQ-DEF-004, REQ-DEF-006): `data["defects"] = defect_counts(log)`; text prints, after the active-change block and before `living spec:`, the open defects line (n > 0) or `defect log: <problem>`; exit 0; with or without an active change (N1).
- **`sdd.py sort-failures <file> [--change <id>]`** (REQ-EVD-005):
  - `require_init`; the change (`project.current`: N3, N4); then `Path(file).read_text()`, where `OSError` or `UnicodeDecodeError` → `cannot read <file>: <reason>` (N1). Nothing is printed before these checks pass.
  - Names: lines stripped, blanks skipped, the first occurrence of each kept (N2).
  - The change's scenarios are its non-removed requirements' `REQ-….X` refs; tasks come from `parse_tasks` in plan order. For each name, the IDs are the change's scenarios whose `scenario_pattern` matches it, ordered by first match position.
  - The first ID with a ticked planner → `regression: <name> (<ID>, <first ticked task> done)`; else the first ID → `expected: <name> (<ID>, <first task> not done)`, or `(<ID>, no task)` (B3); no ID → `outside: <name>`.
  - Last line `sorted: <r> regression, <e> expected, <o> outside the change`; exit 1 when r > 0, else 0; writes nothing.
- **Parser and docstring:** `sort-failures` and `defect` (sub-commands `add`, `decide`, `close`) are added to `build_parser`, and the module docstring lists them. `SddError` → exit 1, as today.

## Test strategy
- One test per scenario in `tests/test_sdd.py`, named `test_REQ_<PREFIX>_<NNN>_<ID>_…`, in new classes `ComponentCommandTests`, `DefectAddTests`, `DefectDecideTests`, `DefectCloseTests`, `DefectCountTests`, `DefectLogTests` and `SortFailuresTests`.
- Integration through `sdd.main()` with the `Repo` helper in a temporary folder, no git and no subprocess; exit 2 comes from argparse's `SystemExit`. "No file is changed" and "byte-for-byte unchanged" compare `snapshot()` or the log's bytes before and after.
- Fixtures: `DesignedBase.designed()` for the standard change at designed (EVD-004, DEF-004.S2, DEF-006.N3), with the design text varied per scenario; `Base.new()` and `Repo.fill()` for the mini draft (EVD-004.B6) and for the 0007-x change (archive folders 0001 to 0006 number it) with T1 ticked and T2 unticked (EVD-005); a `defect_log(*rows)` helper writing the header, the separator and the given rows; a living `cli` (CLI) capability for DEF-001.S3, B3 and B4. The failing-test file is written in the temporary folder and passed as an absolute path.
- No test doubles: the dependency scenarios are a missing or invalid file, built as real files.
- Existing tests that count plan-stage warnings (the `warnings (1):` assertions of the analyze classes) get a valid `- Test component:` line in their design fixture, since the new warning is REQ-EVD-004.B1 behavior; the task says so.
- Mutation check (rule 4): one `## Mutations` entry per new rule (below); the Verifier runs the pinned `SDD mutate` (rule 7).
- Test command: `python3 -m unittest tests.test_sdd`
- Test one: `python3 -m unittest tests.test_sdd.{name}`
- Test component: `python3 -m unittest tests.test_sdd -k REQ_{prefix}_`

## Mutations guidance
Added by the Implementer once each rule's task is green, one entry per rule: component line needs a list marker; more than one line; empty or missing warns; `{prefix}` required; unclosed quote; defect number is max + 1; capability from the first ID; `--capability` wins; capability must be known; one open defect per test; pipe escaped in cells; append without rewriting; header cells compared trimmed; separator dashes; nine cells; allowed values; repeated ID; decide replaces only changed cells; evidence required; line breaks as spaces; closed defect refused by decide; close needs a decision; open counts by severity and decision; invalid log an error only at verify; regression needs a ticked planner; first deciding ID printed; duplicates and blanks skipped; exit 1 only on a regression.

## Method changes (design work, project rule 1)
Edits in `skill/sdd/` of the development checkout, never in the installed skill:
- `method/phases/implement.md`: selection takes a range `T1-T45` besides `T3`, `next` and `all`; the operator authorizes it once and the run goes to its end unless a stop condition occurs (`all` no longer stops "at the first problem"). Three test levels: the task's own test (`Test one:`), the component level (`Test component:` with `{prefix}` replaced) at a checkpoint where the next task's requirement prefix differs or the range ends inside a prefix (one checkpoint per prefix), and the full suite (the design's test command) once before the run closes. Without a component command the run skips the checkpoints and says so (Q3). Failing tests at a checkpoint go through `SDD sort-failures`: expected ones are a count and never stop the run; a regression (the operator's definition: passed before the task, fails after it) the task can't explain stops it; outside ones are judged by the agent from its own runs. Stop conditions: the task's own test still fails after two planned fixes, an unexplained regression, or a spec that is ambiguous or wrong. At the end, each full-suite failure is recorded with `SDD defect add` (severity suggested by the agent), and a triage report lists them and asks the operator for each decision, recorded with `SDD defect decide --evidence "<their words>"`; fix-now becomes a `bug` change or a task, later stays open, and `SDD defect close` records what fixed it.
- `method/roles/implementer.md`: step 3 runs the task's own test only, replacing "plus the tests around it"; the "An unrelated test breaks" row becomes: an expected failure is ignored, a regression is analyzed under the stop rule, an outside failure is judged and recorded.
- `SKILL.md`: the break protocol's "an unrelated test failing" becomes "a regression"; the routing row for implement mentions ranges.
- `templates/mini-spec.md` and `templates/standard/design.md`: a `- Test component:` line after `- Test one:`, with a comment explaining `{prefix}`.
- `method/overview.md`: script table rows for `SDD sort-failures <file>` and `SDD defect add|decide|close`.
- `method/format.md`: the `Test component:` line (list line, `{prefix}`, one per design) and the defect log (columns, values, row text, who writes it).
- `method/roles/spec-author.md` and `method/phases/propose.md`: a capability is a unit of coherent functional purpose (for example checkout, catalog or accounts), small enough to test as one component; the Spec Author proposes the capabilities a change needs and the operator confirms them at the spec gate.
- At delivery: README, RELEASE_NOTES and the version (rule 9).
